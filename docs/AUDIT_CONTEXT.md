## 6. 优先级与不能误读的结论

先读正式报告的 S-01/S-02：当前默认 JWT 与按昵称同步管理员是两项 P0。后续若获得修复授权，应优先关闭身份问题并建立回归。

其余重点：S-03 注入、S-04 数据库暴露、S-05 备份/镜像、S-06 依赖、S-07 会话、S-10 隐私；D-01 至 D-05 的历史保留、天气、时间与事务；然后补字段、坐标、奖励、功能和容量。

必须保留这些限制：

- 昵称注册本身不立即设置 is_admin；提权要求唯一匹配且执行同步。存在多个匹配时会抛异常，影响下一次启动。没有验证真实管理员仍使用种子密码。
- 后台昵称注入在 Node 中执行了无害标记；钓点弹窗只验证不安全 HTML，未执行真实浏览器验证。
- 所有日志公开是当前产品契约，没有已存在的 visibility 保护被突破；应归为隐私设计缺口，不能误写为已证实私密记录 IDOR。
- 删除自己的钓点可删除他人引用记录已复现；删除装备用户则因外键失败而回滚，不能把两者混为同一种现象。
- 点赞只 flush，作者日经验达到 50 时 add_xp 零分提前返回，无 commit；这是“显示成功但不保存”的具体原因。
- 经验丢更新用两个会话先读后写复现；连续 31/32 天奖励验证到天数计算与奖励映射，不是完整 HTTP 发奖测试。
- 时间修复不能统一给存量数据加 8 小时；坐标修复也不能对所有旧点位不加区分地再转换。
- bcrypt 5.0.0 对超过 72 字节密码抛异常；不是静默截断。字符长度与 UTF-8 字节长度不同。
- 已有数据库连接池、上传大小限制、HTTPS 及若干安全头；不要在后续重述时写成完全没有。
- Jinja 沙箱公告要求不可信模板，python-jose 部分公告要求 JWE/特定非对称密钥；本项目未发现这些使用方式。上传解析相关公告与现有路径更直接相关。
- 默认密钥轮换可使现有登录失效；修改 Compose 数据库密码也不会自动改变现有数据库卷中的用户密码。
